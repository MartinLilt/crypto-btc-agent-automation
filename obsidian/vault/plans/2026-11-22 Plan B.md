# План B: две правки стратегии, проверка на истории (2026-11-22)

Основа: аудит 2026-11-22 (Dev Log), memory `bull-bag-tp-gap`, исследование 2026-08-22.
**Работающего бота не трогаем, пока владелец не посмотрит результаты и не скажет «включаем».**

## Что проверяем

- **B1. Продавать позиции сетки («мешки») по цели и в бычьем режиме (BULL).** Сейчас в BULL
  сетка заморожена целиком: позиции не покупаются и **не продаются**
  (`main.py`, ветка BULL; в симуляторе тот же `continue`).
  Живой пример 2026-10-09: позиция BTC +7.7%, SOL +18.5% при цели 0.6%.
  Правка: в BULL продавать позиции, достигшие цели; новых позиций в BULL по-прежнему не покупать.
- **B2. Режим только по закрытым дневным свечам UTC.** Сейчас «дневная свеча» = последние
  24 часа, считая от текущего 4-часового бара, поэтому режим может смениться в любом цикле.
  Живой пример: 2026-10-12…10-15 холды 8 раз проданы в минус, всего −1.19.
  Правка: режим считается раз в сутки по дневной свече, закрытой в 00:00 UTC, и держится до следующей.
- **B3.** Обе правки вместе, если каждая прошла по отдельности.

## Правила (заданы ДО запуска, после результатов не меняются)

1. **Парное сравнение:** те же данные, те же бары, меняется одна вещь. Базой служит симулятор с живыми
   настройками (holdout 25%, частичная фиксация 40%/50%, TP 0.6%, шаг 0.8%).
2. **Срезы:** полный период; H1 (до 2025-02); H2 (2025-02 → 2026-08-22);
   **H3 (2026-08-22 → сейчас)**. H3 — новые данные, которых исследование августа не видело.
3. **Сдвиг часа:** те же 4-часовые бары, собранные из 1h со сдвигом 0/1/2/3 ч. В августе
   такой сдвиг давал разброс 16–24 п.п. Реальный эффект от него не зависит.
4. **Правка проходит, только если:**
   - доходность лучше базы в полном периоде **и** в H1 **и** в H2;
   - в H3 не хуже базы;
   - лучше хотя бы в 3 из 4 сдвигов часа;
   - максимальная просадка не хуже базы больше чем на 2 п.п.;
   - **механизм подтверждён:** выигрыш пришёл оттуда, откуда должен. Для B1 растёт P&L сетки
     за счёт продаж в BULL. Для B2 становится меньше коротких холдов и продаж в минус.
5. Новых параметров не подбираем: ни TP для BULL, ни порогов режима. Одна правка, одна проверка.
   Если хочется «подкрутить», это новый пункт с новыми правилами.
6. Отрицательный результат тоже результат: записываем его в Dev Log и в список отвергнутых идей.
